## 性能:标题解析 16.9 s → 3 ms(缓存 + 分层能力探测)

### 问题

`s2s_message` / `s2s_sessions` 的寻址(name → sessionId)每次都要枚举整个会话语料并**逐个解包日志取标题**,且结果完全不保留。实测:233 个日志文件、**855,034 个 zstd 帧**,一次全量解码 **9.1 s**;`discovery.list()` / `resolve(name)` 实测 **16.6 s / 16.8 s**,第二次调用同样耗时。

投递本身是进程内同步直投,所以一次 s2s 调用的开销几乎全在寻址上,且随语料规模线性复利。

### 修复:能力探测的分层解析

按代价从低到高,每层用 `typeof === 'function'` 探测,缺失即整层跳过并下落:

| 层 | 手段 | 成本 | 适用宿主 |
|---|---|---|---|
| **L0** | 本地标题缓存(内存 Map + 持久 JSON 文件) | ~0 | **所有版本** |
| **L1** | `sessionProjectionCache.cachedSnapshot(header, ['title'])` 零 I/O 列举读 | ~0,同步 | 0.1.7+ |
| **L2** | `readTitleSnapshots(ids)` 一次语料观测 | 一次观测 | 0.1.7+ |
| **L3** | 逐条 `readTitle(id)` | O(N) | 0.1.5 及以下 |
| **L4** | 磁盘扫描 + 多帧 zstd 解码 | O(N) 次(仅首次) | `sessionQuery` 缺席 |

**L0 是唯一跨版本通用的加速层** —— peer 范围声明到 `^0.1.0-rc.6`,老宿主没有 L1/L2,但一样受益。L3/L4 完整保留,是那些版本的唯一路径。

### L0 的失效模型:惰性、事件驱动

**日志文件变化不触发重解。** 仅在下列事件发生时才重读:

- **E1** 找不到(未缓存)
- **E2** 找错了(同名冲突,记为 ambiguous,不再由缓存单独作答)
- **E3** 被主动要求重找(`forgetCachedTitle`)
- **E4** 条目超过 24h 未访问

代价(已接受):会话改名后旧名会继续命中,直到触发 E1–E4 之一。按 **session id 解析永不受影响**(id 不可变),且陈旧条目**不会指向无关会话**。

### 持久化的启用条件

仅当部署显式声明了 DSH 主目录(`DSH_HOME` / `DSH_DATA_DIR`)时才落盘;未声明时退化为纯内存缓存。这样单元测试与临时嵌入**不会写入用户真实的 `~/.dsh`**。

### 实测收益(真实语料:238 会话)

| 路径 | 耗时 |
|---|---|
| L4 冷启动(逐帧解码全部日志) | **16,935 ms** |
| **L4 热启动(L0 缓存命中)** | **3 ms** |
| `resolve(name)` 经 L0 缓存 | **0 ms** |
| L1(投影缓存) | **3 ms** |

标题结果完全一致(156/238),纯加速、无语义变化。

### 测试

新增 16 条用例,覆盖:**缓存命中零读取**、E1/E2/E3/E4 四种失效、**仅改文件不重解(锁定惰性语义)**、跨重启持久化、L1 命中/L1 miss→L2 单次批量/L1 无标题行也算答案/L1 抛错不破坏枚举、**pre-0.1.7 宿主(无投影缓存且无批量 API)经 L3 仍可用且 L0 生效**、按 id 解析零枚举,以及缓存文件损坏/版本不符的容错。

全部 115 测试通过。
